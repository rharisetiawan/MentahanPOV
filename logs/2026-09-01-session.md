4. **Bumped `PIPELINE_TIMEOUT_S`** to 1 hour (from 30 min) — the HG680 is

5. **Three production incidents on the HG680, all fixed and documented in
   `DEPLOYMENT.md`'s incident log** (read that file for full details —
   this is just the index):
   - **IPv6 route broken** → intermittent `Network is unreachable` on
     Gemini/Drive/Graph calls. Fixed with a per-container sysctl in
     `docker-compose.yml`.
   - **Gemini 503 "high demand", then 429 rate limits, then a retired
     fallback model** (`gemini-2.0-flash` and even `gemini-2.5-flash-lite`
     both 404 now — Google retires model names with little warning, and
     `models.list()` still lists dead ones). Fixed with split
     upload/retry logic + `GEMINI_FALLBACK_MODEL` (now
     `gemini-3.5-flash-lite`, verified live). **This will need attention
     again whenever Google retires a model — see the comment above
     `gemini_fallback_model` in `config.py` for how to verify a
     replacement before trusting it.**
   - **Google OAuth tokens expired** (`invalid_grant`) — the OAuth consent
     screen is in Testing mode, so refresh tokens die ~7 days after
     original grant regardless of use. Re-authenticated by running the
     OAuth flow on the dev laptop (real browser) and copying fresh
     `gdrive-token.json`/`youtube-token.json` to the box. **This will
     recur roughly weekly** unless the app is moved to Production status
     (not done — likely needs Google verification for the `drive` scope).
     Full re-auth steps are in `DEPLOYMENT.md` → "Re-authenticating Google
     OAuth".

6. **Built proactive health monitoring** so the next incident doesn't have
   to be discovered by a failed video send:
   - `core/health.py` — shared checks for Drive/YouTube/FB/IG/Threads/
     Gemini/disk space.
   - Telegram `/status` command (on demand).
   - Daily automated report at `DAILY_STATUS_HOUR` to
     `TELEGRAM_ALLOWED_USER_IDS`.
   - `dashboard.py` — password-protected, LAN-only web status page
     (new `dashboard` service in `docker-compose.yml`).
   - **Committed to GitHub but NOT YET DEPLOYED to the HG680** — see
     "Pending" below.

7. **Backed up the production Docker setup itself** (`Dockerfile`,
   `docker-compose.yml`, `.dockerignore`) to git — these only ever lived
   on the box before, so losing it would've meant reverse-engineering the
   whole deployment from scratch.

8. **Fixed a git push permission mix-up**: this laptop has two GitHub
   accounts cached (`rharisetiawan` and `weverxcom-hub`) via Windows
   Credential Manager. Fixed by scoping this repo's remote URL to
   `https://rharisetiawan@github.com/...` instead of deleting the other
